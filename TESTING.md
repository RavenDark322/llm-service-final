## Находки при тестировании

**1. Модель нарушала контракт ответа из-за инструкции пользователя.** Первый прогон сценария `answer` вернул 502
`llm_invalid_response`. По событию `llm_response` в логе (профиль dev пишет сырой ответ) видно, что GigaChat ответил
по существу, но простым текстом, а не JSON: вопрос заканчивался фразой «Ответь в одном предложении», и модель выполнила
последнюю инструкцию, забыв требование формата из системного промпта. Сервис отработал корректно (переспросил модель
и отдал fallback), но для пользователя это отказ. **Исправление:** требование формата дублируется в конце сообщения
пользователя (`format_reminder` в `config.yaml`), ключ кеша строится по всем сообщениям, уходящим в модель.
После исправления — 200 и корректный JSON (R1).

**2. Автотесты подменяли файл сертификатов работающему сервису.** Следующий прогон дал 503
`TLS certificate verification failed`, хотя сертификат не менялся. Причина: склеенный набор сертификатов писался
во временный файл с фиксированным именем, а тест проверки склейки, запущенный параллельно с сервисом, перезаписывал
его другим содержимым. **Исправление:** имя файла — по SHA-256 содержимого, запись атомарная (временный файл + замена);
добавлен регрессионный тест `test_different_ca_bundles_do_not_overwrite_each_other`.

**3. Поведение сети зависит от ОС.** Тест «сеть недоступна» падал на Windows: на закрытый порт Linux сразу отвечает
отказом в соединении, а Windows повторяет попытку и упирается в таймаут подключения. Для сервиса оба случая —
временная ошибка с ретраями и fallback; тест теперь проверяет класс ошибки, а не текст, зависящий от ОС.

**4. Smoke-тест в CI стартовал раньше приложения.** Первый запуск CI упал на этапе Docker: образ собрался,
но проверка `/health` выполнилась через 15 мс после `docker run`, когда приложение ещё не слушало порт.
Docker-прокси принимал соединение и сбрасывал его (`curl: (56) Connection reset by peer`), а флаг `--retry-connrefused`
такую ошибку не повторяет. **Исправление:** явное ожидание готовности — цикл до 30 с с повтором при любой ошибке;
во втором запуске сервис здоров через 2 с, все проверки зелёные. Диагностика — по логу упавшего шага в GitHub Actions.

Находки 1–3 не воспроизводились автотестами на Linux и проявились только при живом прогоне на Windows
с реальным GigaChat — поэтому в проекте есть и CI, и ручные сценарии.
